# 종합실습 설계 문서

## 문제와 대상 사용자

학교·학과·단체명을 알고 있는 사용자가 해당 단체의 물품 수량, 개별 상태와 대여 조건을 자연어로 확인하도록 돕는다. 사용자 소속 조회 기능은 없으므로 사용자가 입력한 키워드를 수집 범위로 사용한다.

## 데이터 범위와 수집

Swagger 문서가 아니라 세 public 조회 API의 실제 응답을 텍스트로 변환한다. 단체 검색은 문자열 cursor, 물품 목록은 정수 cursor를 순회한다. 단체 ID와 물품 ID로 중복을 제거하고 상세 경로의 itemId로 목록과 상세를 결합한다. 목록에서 단체 ID가 다르면 실패 처리한다.

각 새 스냅샷은 문서와 manifest로 구성한다. manifest에는 수집 키워드, 시작/종료 시각, 요청 수, 오류, 단체별 목록 완료 여부, 문서 메타데이터가 있다. 이미지 URL과 인증 헤더는 저장하지 않는다. 목록 수집 시각과 상세 조회 시각은 구별하며 수집은 원자적 시점 조회가 아니다. 일부 실패한 스냅샷도 확인 가능한 정보는 보존한다.

문서에는 단체/물품 이름과 ID, 수량, 활성 여부, rentalDuration 원값, 설명, 담보 물품, 관리 유형, 개별 유닛 상태, 입력 요구 정보, level 원값, 출처 URL과 시각을 담는다. null과 누락은 확인 불가로 표시한다. 빈 개별 유닛 목록을 물품 없음으로 간주하지 않는다.

## Baseline

```text
API → 물품별 문서 + 단체 목록 + manifest
    → TextLoader → Splitter(본문 900자, overlap 150자)
    → 각 청크에 식별/출처/시각 헤더 복원
    → text-embedding-3-small → FAISS similarity Top-3
    → 근거 제한 Prompt → gpt-4o-mini(temperature=0)
```

긴 문서가 나뉘어도 소속 단체가 소실되지 않게 한다. 검색 원문과 메타데이터를 평가 결과에 저장하여 출처를 확인할 수 있다. 기존 강의 예제와 rag_core.py는 변경하지 않는다.

## 개선 후보

BM25와 벡터 검색의 후보를 각각 max(3×k, 10)개 수집하고 RRF 상수 60으로 합쳐 같은 Top-K를 반환한다. BM25 토큰은 영문/숫자/한글 단어와 한글 2-gram이다. 별도 형태소 분석 의존성 없이 조사와 붙여 쓴 단체명에 대응하려는 선택이다.

이는 정확한 단체명·물품명 검색을 보완하기 위한 후보 구현이다. mock Baseline 관찰 후 비교한 결과, 다른 단체 청크 수는 줄었지만 정답 검색률은 같았다. compare는 Baseline 결과 파일과 관찰 이유를 요구한다. 상세 실측과 채택 범위는 아래 실험 후 결정 및 evaluation.md를 따른다.

## 평가

실제 수집 데이터에서 prepare로 질문 10개를 생성하고 사람이 검토한 후 고정한다. 기본 수량, 표현 변경, 정확한 이름/ID, 복합 조건, 문서에 없는 정보를 포함한다. 데이터·메타데이터·질문 해시와 모델/Top-K/생성 여부가 다른 Baseline으로 비교할 수 없다.

Retrieval Hit는 정답 문서 ID와 근거 문자열이 같은 검색 청크에 모두 포함되는지 측정한다. 답할 수 없는 질문은 분모에서 제외한다. 복합 질문의 완전한 근거 충족은 검색 원문과 Generation 수동 검토로 보완한다. Hit가 정답 전체의 충분성을 보장하지는 않는다.

Generation은 근거 일치, 질문에 직접 응답, 무근거 질문의 답변 제한을 별도로 사람이 판정한다. 수집 시각/출처 표시, 수량 차이의 잘못된 해석, 전체 목록 단정 여부도 notes에 기록한다.

## 한계

수집 키워드 밖의 단체는 찾을 수 없다. 수집 후 상태가 바뀔 수 있다. 각 페이지/상세 조회 시점이 다르며 API가 제공하지 않는 조건은 추정하지 않는다. Top-K 검색으로 전체 목록을 보장하지 않는다. 문서 내부 지시 무시와 근거 제한은 Prompt 정책이며 모델의 완전한 준수를 보장하지 않으므로 실제 생성 평가가 필요하다. 현재 고정 질문 생성기는 수집된 물품을 순환 사용하므로 데이터가 적으면 다양성이 부족할 수 있다.

## 2026-10-02 실험 후 결정

주 실험 데이터는 `data/mock/experiment-v1`의 가상 단체 5개·물품 24종으로 변경했다. mock과 실제 데이터는 디렉토리·manifest.data_kind·문서 표시·출처 호스트로 구별한다. 테스트 서버의 빈약한 데이터로 운영 성능을 평가하지 않는다. 운영 최종 대상은 `https://www.retrivr.kr/`이며 실제 연결/명세/인증 검증은 아직 수행하지 않았다.

Baseline은 정답 검색에 성공했으나 Top-3에 타 단체 동명 물품이 포함됐다. Hybrid는 타 단체 청크 수를 줄였지만 Hit Rate와 주요 답변 정확도는 같았다. 실제 실패는 대여 기간 단위 추정이므로 검색과 별도로 `STRICT_PROMPT`의 메시지 분리/기간 규칙을 적용했다. 이후 발견된 목록 수집 실패 오인은 `collection_failure_answer`로 명시적인 확인 불가 안내를 반환한다. 이 처리는 질문에 단체 전체 이름이 있으며 해당 수집 실패 목록 문서가 검색된 경우에만 적용한다.

최종 비교는 검색 결과를 고정해 생성 변경만 검증했으며 결과와 회귀는 evaluation.md에 기록했다. 10문항의 작은 단일 mock 실험이므로 일반적인 우수성을 주장하지 않는다.
